## 原画像との照合範囲

- 全音の音高・オクターブ・音価・付点・和音構成を原画像と照合しました。
- 臨時記号は譜例1の A♮3、D♮4、G♮2、A♮2、譜例4の B♯5、F♮5、F♯5、G♮5、B♯4、B♮4 を確認しました。
- 譜例1/2はヘ音記号、3/4はト音記号。調号・拍子は画像に見えるものだけ保存しています。
- 4譜例とも画像に休符はなく、校正済みデータにも補っていません。
- 譜例1の通常のタイ3本＋末尾の継続タイ2本、譜例2のスラー2本、譜例3のスラー7本、
  譜例4のタイ2本・スラー11本（装飾音と末尾継続を含む）を SVG でも確認しました。
- アクセント3個、`pp` / `p` / `ff`、速度標語、`marcato` / `dim.` / `espr.` と既存キャプションを保持しました。
- 譜例1/4の末尾は原画像自体が曲線を切り抜いています。画像外の音高や音価は推測して追加していません。

音符列と完全小節の長さを `test:scores` に記録し、符尾の誤認識や第3小節の欠落が再発しないよう検証します。
MusicXML の座標情報を除き、清書上の文字位置・書体・連桁の傾きは Verovio に任せています。
画像からの自動認識結果が音楽的に正しいことを保証するものではありません。

## PoC の評価

- **認識精度**: 単純な譜例1/2の音符は良好でした。符尾、装飾音、重なるタイ／スラー、
  小節線のある譜例3/4では音楽的な誤認識が残り、完全自動掲載には不十分です。
- **校正量**: 1/2は記号・抜粋境界の確認が中心。3は音符2個の除去と音価2個の修正。
  4は小節の再構成を要し、原画像との逐音照合が必要でした。作業時間の厳密な計測は行っていません。
- **SVG 品質**: 譜面は埋め込みパスで描画され、ラスターデータや外部の楽譜フォントに依存しません。
  拡大しても音符・付点・臨時記号の輪郭を保持します。末尾の継続曲線にはレンダラー側の MEI 補助が必要です。
- **表示確認**: Chromium で画面幅 320px / 375px / 600px / 601px / 768px / 1280px の記事を表示し、
  4点の画像読み込み、キャプション、譜例とページ全体の横はみ出しがないことを確認しました。
  600px 以下では複数段の SVG を選び、全譜例が横スクロールなしで読めます。
  1280px / 375px の新旧表示を前後の本文とともに [比較スクリーンショット](pr-69-screenshots/README.md) に保存しました。
- **新規記事への適用**: 同じ CLI と `<Score>` を再利用できます。OMR と掲載用正本を分離するため、再認識で校正が失われません。
- **実行場所**: OMR/校正はローカル、SVG は事前生成、CI/build はテストと再生成一致の検証が適切です。
  毎回の OMR には認識の不確実性と Java/OCR データの負担があります。
- **Git 管理**: 画像・正本・生成 SVG は保持します。未校正 MXL は trial の証跡として保持し、大きな `.omr` やログは除外します。
